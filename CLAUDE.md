# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What Is This?

Faucet is an open-source Go application that turns any SQL database into a secure REST API. It ships as a single binary with no required configuration and includes an MCP server for AI agents. Supported drivers: PostgreSQL, MySQL (also used for MariaDB), SQL Server, Oracle, Snowflake, SQLite.

Sibling repos are checked out next to this one in `/root/FAUCET`: `wiki/` (VitePress user docs), `marketing-site/` (Astro, faucetdb.ai), and `homebrew-tap/` (formula generated by GoReleaser, so don't edit it by hand). When behavior visible to users changes, update `wiki/docs/` as well.

## Stack

- Go 1.25 (see `go.mod`), Chi router, `jmoiron/sqlx`, Cobra + Viper CLI, `mark3labs/mcp-go`
- Config/metadata store: embedded SQLite (`modernc.org/sqlite`, pure Go, `CGO_ENABLED=0`)
- Admin UI: Preact + Vite + Tailwind v4 in `ui/`. `vite build` writes to `internal/ui/dist`, and `internal/ui/embed.go` embeds it with `go:embed`. The built `dist` is committed (force-added despite `.gitignore`) so `go install` users get the UI; rebuild and re-add it when UI code changes. Read `ui/STYLEGUIDE.md` before changing pages: colors are CSS variable tokens in `src/index.css`, shared building blocks live in `src/components/ui.tsx` and `Overlay.tsx`, and engine metadata lives in `src/lib/drivers.ts`. Run `npm run typecheck` in `ui/` (CI does too)

## Commands

```bash
make build            # UI (only if ui/node_modules exists) + Go binary -> bin/faucet
make build-go         # Go binary only
make dev              # go run ./cmd/faucet serve --dev (verbose logs, CORS *)
make dev-ui           # Vite dev server; proxies /api, /healthz, /openapi.json to :8080
make test             # go test -race -count=1 ./...
make lint             # golangci-lint run ./... (v2 config in .golangci.yml)
make fmt              # gofmt -s + goimports

go test -race -run TestName ./internal/query/     # single test
FAUCET_INTEGRATION=1 go test -v ./internal/connector/   # integration tests
```

CI (`.github/workflows/ci.yml`) runs the UI build, `go vet`, `go test -race`, golangci-lint v2.4 and `go build`.

Integration tests are gated by the `FAUCET_INTEGRATION=1` env var, not by a build tag. Without it, `TestMain` exits early. They connect to remote demo databases, not to local Docker containers. `make test-integration` passes `-tags=integration`, which does nothing on its own.

`faucet serve` daemonizes by default: it re-execs itself with `--foreground` and writes a PID file. Use `--foreground` (or `make dev`) when running interactively. `faucet stop` stops the daemon. State lives in `~/.faucet` (override with `--data-dir`).

## Architecture

Request flow: `cmd/faucet/cli` (Cobra) → `internal/server` (Chi router + middleware) → `internal/handler` → `connector.Connector` (one per configured "service") → database.

- **Services and the registry.** A "service" is a named database connection stored in the SQLite config store (`internal/config`). At startup, `cmd/faucet/cli/helpers.go` registers driver factories with `connector.Registry` and connects each service. Handlers look up connectors by service name. A new driver needs a package under `internal/connector/<driver>`, a `RegisterDriver` call in `helpers.go`, DSN handling in `connector.SanitizeDSN`, a field builder and parser in `internal/connector/dsn.go` (`BuildDSN` and `DescribeDSN`, used by the UI's host/port/user form, the API's `connection` object and `faucet db add --host ...`), and an entry in `ui/src/lib/drivers.ts`.
- **Connectors own SQL dialect.** The `Build*` methods return `(sql, args)`. Handlers never build SQL strings themselves. Shared parsing lives in `internal/query`: the filter parser turns the `filter=` syntax into parameterized SQL fragments, and it also holds aggregates and identifier sanitization.
- **Routes** (`internal/server/server.go`):
  - `/api/v1/system/*`: admin only (JWT session). Covers services, roles, API keys, admins and contracts.
  - `/api/v1/{service}/_table|_schema|_proc|_doc`: data API. The middleware chain is `Authenticate` → `RequireAccess` (RBAC) → `ReadOnlyGuard`.
  - `/mcp`: Streamable HTTP MCP, authenticated.
  - `/openapi.json`: combined spec.
  - The rest serves the embedded SPA.
- **Auth and RBAC** (`internal/rbac`): principals are admins (JWT, which bypass RBAC) or API keys bound to a role. Roles grant `verb_mask` per service/component pattern, and access fails closed. Matching is case-sensitive. Services flagged `read_only` reject writes regardless of role.
- **MCP** (`internal/mcp`): tools are prefixed `faucet_*`. MCP calls don't go through the HTTP middleware, so MCP code calls `rbac.Enforcer.Authorize` itself. Any new tool or resource must do the same. `faucet mcp` (stdio) runs as an admin principal, while `--transport http` and the `/mcp` route use the caller's principal.
- **Schema contracts** (`internal/contract`, `handler/contract.go`): lock modes are `none`, `auto` and `strict`. A contract freezes the API shape of a table. `contract/diff.go` sorts live schema drift into additive changes (auto-promoted in `auto` mode) and breaking ones (which need explicit promotion).
- **OpenAPI** (`internal/openapi`): a 3.1 spec generated from introspected schemas, per service (`_doc`) and combined.
- **Telemetry** (`internal/telemetry`): PostHog. The key is injected via ldflags, so builds without the key send nothing. Users can opt out with `FAUCET_TELEMETRY=0`. See `TELEMETRY.md`.
- **Viper env mapping**: nested keys map to `FAUCET_*` with `.`→`_`, so `auth.jwt_secret` becomes `FAUCET_AUTH_JWT_SECRET`. On first run, `FAUCET_ADMIN_EMAIL`/`FAUCET_ADMIN_PASSWORD` bootstrap the admin.

## Conventions

- Filter values MUST be parameterized, never string-interpolated. All table and column names must pass `query.ValidateIdentifier()`, and quoting goes through `Connector.QuoteIdentifier`.
- List responses use `{"resource": [...], "meta": {...}}`. Errors use `{"error": {"code": N, "message": "...", "context": {...}}}`.
- API keys are stored SHA-256 hashed. Admin passwords are bcrypt hashed.
- Tests use the standard `testing` package only, with no assertion frameworks. Handler tests use `httptest` against a real router (see `internal/handler/handler_test.go`).

## Release

Pushing a `vX.Y.Z` tag triggers `release.yml`, which runs GoReleaser. GoReleaser builds the GitHub release, the Docker image (`Dockerfile.goreleaser`) and the Homebrew formula (it pushes to `homebrew-tap`). `npm-publish.yml` publishes `@faucetdb/faucet` plus 6 per-platform packages from `npm/`, using `scripts/npm-publish.sh`, and only for final release tags. CONTRIBUTING.md covers the npm auth setup (OIDC or `NPM_TOKEN`).
